# 项目数据源接入与同步

## 使用边界

Workstation 可以从 GitHub、GitLab 获取仓库资料和开发情况，并保存到当前 Workspace 的 MySQL 数据库。代码托管平台提供源事实，工作台保存带同步时间的快照；页面读取快照，不依赖每次访问时平台在线。

一个工作台项目可以关联多个仓库。平台实例与外部仓库 ID 决定资源身份，仓库改名不会新建项目。GitLab 支持 gitlab.com 及部署管理员明确允许的自建 HTTPS 实例。GitHub 目前支持 github.com。

工作台项目名称、描述、状态、技术栈、运行说明、项目入口以及手写仓库地址由用户维护。首次导入可用仓库名称与描述初始化项目，后续同步只更新源资料，保留本地项目资料、任务和笔记。项目入口由 homepageUrl 表达；完整更新请求需要明确提交该字段，null 表示清除。

## 部署准备

上线前先备份目标数据库，再执行仓库中的 migrate-project-integrations.sql 历史迁移。新安装的完整初始化顺序以 [部署流程](ci-cd.md) 为准；开发与生产 Compose 已挂载初始化脚本，外部数据表只维护一份定义。初始化脚本不会自动升级已有数据卷；即使尚未启用连接功能，项目新字段与关联表也需要完成迁移。历史项目资料与原有仓库地址保留，不根据 URL 自动绑定远端账号。

数据源默认关闭。部署管理员参照 [.env.docker.example](../.env.docker.example) 或 [Backend 示例配置](../backend/.env.example) 配置功能开关、凭证加密密钥、密钥版本、允许的 GitLab 实例、请求超时、分页与采集上限、租约和近期窗口。开发与生产 Compose 均转发这些配置。

凭证加密使用 32 字节随机密钥的 Base64 表达，密钥仅由运行环境提供，与数据库备份分离。默认新写入使用 v1；轮换时保留旧密钥版本用于读取旧连接，再由管理员重新保存连接，以新版本重新加密。配置示例不包含真实密钥。丢失历史密钥后需重新提交对应平台凭证，不能只恢复数据库便恢复同步。

配置中 v1 对应 INTEGRATIONS_ENCRYPTION_KEY，v0 对应 INTEGRATIONS_PREVIOUS_ENCRYPTION_KEY。轮换时保留原版本槽位的密钥，将新密钥放入另一槽位并切换写入版本；仍有旧版本连接时不能覆盖其密钥。

只开放管理员允许的 GitLab 实例，出站 API 禁止重定向，不使用平台返回的任意下一页地址发送凭证。GitHub API 地址固定；GitLab 允许的内网实例也是明确的出站授权。生产统一入口保持 HTTPS。

## 连接账号和选择范围

只有 Workspace 的 OWNER、ADMIN 可以管理连接及触发同步；Backend 通过集中 Permission 校验保证这一边界。普通成员按项目读取权限查看已经共享到空间的开发摘要。

“数据源”首页展示连接及其同步状态。点击“添加连接”打开编辑抽屉，选择平台与实例，提交只读平台访问 Token；点击已有连接进入详情，通过仓库、执行记录和连接设置分别浏览结果与管理配置。GitHub 使用具备目标仓库权限的 PAT；GitLab 使用可读取目标项目的 Token。Token 仅暂存在输入表单，通过工作台受认证且具有 CSRF 保护的写接口提交后或关闭抽屉时清空，服务端加密保存，不回显。

连接验证确认账号身份，不等于所有开发接口权限均已获得。GitHub 仓库资料、Contents、Issues、Pull requests、Actions 等能力需要按实际接口配置只读权限；组织审批、仓库授权、账号与 Token 类型会影响可读范围。GitLab 的项目或群组 Token 也不能等同于个人账号的所有项目权限。

“本人拥有”与“本人及参与的组织/协作仓库”是两个发现范围，可以进一步选择是否包含 Fork 和归档仓库。全部仓库始终受连接的实际权限约束，不包含无法读取的资源，也不包含 GitHub Projects 看板或源代码全文。

共享 Workspace 配置连接与导入时确认共享边界：包括私有仓库在内的导入数据会按该空间成员权限共享，不要求每位成员都有独立平台账号权限。个人私有数据适合首先导入个人空间。

## 仓库发现、导入和关联

先执行“发现仓库”，后台按页保存候选仓库摘要。发现失败或触及分页上限时，候选列表可能不完整，执行记录不会报告完整成功。

关闭自动导入时，发现只保存候选仓库。在连接详情的仓库页勾选结果，再点击“继续导入”，在独立抽屉选择按仓库新建项目，或将所选多个仓库关联到一个已有项目，并确认共享范围；选择可跨页保留，每次手动导入最多 100 个仓库。新项目状态由导入表单明确选择，默认 PLANNING。每个仓库在同一 Workspace 最多绑定一个项目，重复导入返回已有绑定结果。

开启“自动为所选范围的所有新仓库创建项目”后，发现或定时同步会为未关联的新仓库创建规划中的项目。因此首次全量导入也可以使用这个开关；启用前检查账号范围和共享确认。后续同步新发现的资源也适用该行为。

同一仓库被另一个连接管理时，本次发现不自动更换其凭证来源。更换连接可先移除原连接再用新的同实例连接发现，验证后保留仓库身份和项目关联。

## 手动同步与定时执行

“同步已关联仓库”更新源资料，并分别采集 Issue、PR/MR、默认分支近期提交和默认分支流水线运行。只同步已经绑定项目的仓库；开启自动导入时会先重新发现范围内的新仓库。

设置分钟间隔后由 Backend 定期入队。任务和逐项选择持久化在 MySQL，受控线程与 XXL-JOB 可执行同一领取服务；XXL-JOB 可以调度 integrationQueueJob 和 integrationScheduleJob，服务内的周期任务同时作为队列恢复入口。数据库租约防止同一连接并发执行，执行版本防止过期线程继续提交。

关闭定时频率不会取消已排队的手动任务；暂停连接或更新配置会取消旧任务。手动和定时入口对正在执行的连接避免重复入队。后台重新校验连接原主体与触发主体的成员权限，没有浏览器会话也不会绕开 Workspace 授权。

连接的创建主体离开空间或失去管理权限后，自动执行暂停或取消。管理员需要重新提交凭证来接管该连接，不能只用旧连接的已有凭证静默接管。机器主体的审计类型由持久化主体记录决定。

## 外部 API 共享限流与冷却

所有平台请求（含连接账号验证、仓库发现、同步、Issue 指定刷新和网络失败后的重试）先通过 Redis 令牌桶申请额度。额度按平台、规范化实例地址与 Token 摘要共享，相同 Token 在不同 Workspace 或连接中使用同一预算；Redis Key 不包含明文 Token。不同 Token 即使属于同一平台账号也不自动合并，部署额度只是本应用的请求节奏，不代表平台真实剩余额度。

默认桶容量为 5，每秒补充 1 个令牌。所有 Backend 执行器必须使用同一个 Redis 和相同配置。Lua 使用 Redis 时间原子完成补充、扣减与冷却检查；冷却只允许延长，空闲 Key 自动过期。Redis 状态丢失后额度重新初始化，不能替代平台配额限制；生产需为 Redis 设置合适的内存和持久化策略。

收到 429、带限流标记的 403 或 GitHub 次级限流提示后，按照 Retry-After 的秒数或 HTTP 日期、剩余额度为零时的重置时间，选择较晚的有效时间并保留安全余量。缺失或异常提示使用默认 60 秒冷却，其他权限拒绝仍按原错误处理。超过七天的异常提示不直接用于无限延期。已经在途的请求无法撤回，后续请求遵守共享冷却。

额度不足、平台冷却或 Redis 不可用时，后台任务保留为 QUEUED，持久化下次可执行时间与脱敏原因，释放当前租约；到期后重新领取，并继续校验连接配置、成员权限及执行租约。Redis 不可用默认延期 30 秒，不直接放行平台请求；平台冷却已知而 Redis 写入失败时，当前任务仍至少等待该冷却时长。周期领取的实际执行时间可能晚于到期时间。暂停连接或修改配置仍可取消延期任务。

仓库发现保存下一页，开发采集保存当前仓库、类别、固定窗口、页码及有界中间结果；类别快照与进度在同一事务提交，采集中受限不会覆盖已有快照或记为来源失败。Issue 批量游标与 Webhook 逐项目标继续沿用原有持久化恢复规则。远端分页期间数据仍可能变化，此能力不承诺平台数据的事务快照或严格公平调度。

连接创建和验证是交互请求，遇到限流返回现有 BUSINESS_ERROR 业务错误，管理员稍后重试；不会自动生成一个后台连接保存任务。当前执行记录通过已有排队状态与错误说明展示等待原因，不新增公共 API 字段。

已有环境需要在维护窗口暂停全部旧执行器并备份，执行 [限流队列迁移](../backend/src/main/resources/db/migrate-external-api-limits.sql)，再切换配套 Backend；不可混用忽略延期字段和检查点的旧执行器。全新安装由 Compose 在来源确认迁移后执行。新增配置见示例环境文件；Redis 使用已有服务与独立 Key 前缀，Backend 源码调试也需配置 Redis 连接。

## 查看开发情况

项目详情显示关联仓库、源快照时间、各能力采集结果与分页记录；概览显示已关联仓库近期采集的开放 Issue、PR/MR 和默认分支最近流水线结果。

默认采集最近 30 天的变化，每类每仓库最多保存 300 条；管理员可调整范围和上限。Issue 和 PR/MR 数量是这个窗口内已采集的开放条目数，不代表所有尚未完成的事项。GitHub Issue 接口中的 PR 被单独识别，避免重复计数。流水线来源为 GitHub Actions 或 GitLab Pipeline，不包含全部第三方检查。

PR/MR 的开放、合并、关闭状态与工作台任务状态分离；外部状态保留原始值。GitHub Issue 可按下述流程关联工作台任务；不修改远端状态。提交只反映声明的分支和窗口，不用于计算项目完成百分比。GitLab 仓库资料接口未提供推送时间时显示未提供，不用一般资料更新时间替代。

缺少权限、采集失败、未启用流水线或尚无运行不会显示成成功或完整的零数量。超过记录或分页上限会显示截断；刷新页面不会隐瞒这种不完整性。工作台本地项目修改时间与源资料同步时间分开。

## GitHub Issue 与本地任务

项目详情的 GitHub Issue 记录提供“创建任务 / 关联已有任务”。仅处理已采集的 Issue，不接受任意来源地址，不支持 PR、GitLab、批量转化或远端写回。已关联记录提供本地任务入口。

创建时预填来源标题，用户确认本地标题、描述、状态、优先级、截止日期和同项目依据笔记。标题超过 200 字时需调整，不静默截断。关联已有任务只增加来源关系，不改变原任务内容。操作需具备任务写入和项目读取权限，并明确确认来源信息按当前 Workspace 权限共享，包括私有仓库快照。

同一 Workspace 的一个 Issue 最多关联一个任务，一个任务最多关联一个 Issue；不同空间分别维护。并发或重复创建返回已经提交的任务，不覆盖它的字段。指定其他任务争抢同一来源时返回关联冲突。普通任务请求不携带来源字段，也不会清除已有关系。

本地任务的标题、描述、状态、优先级、截止日期与依据笔记由用户维护。来源标题、开放或关闭状态、关闭原因、地址和更新时间由 GitHub 提供；不持续复制正文，不依据标签推导优先级，不按同名账号匹配成员。来源关闭不自动完成任务，来源重开不自动重开任务。页面仅提示当前状态差异；“将本地任务标记为完成”只修改本地状态。

任务卡片和编辑抽屉显示来源，卡片展开可查看最后成功时间、最近尝试及异常。没有读取权限的成员不能访问来源；只读成员可查看共享快照，不能创建、关联或解除。建立和解除关系沿用现有审计流程。

### 来源持续跟踪

关联保存持久化平台身份，不依赖近期快照的临时记录 ID。近期快照重建或 Issue 超出时间窗口与条数上限不会删除关联。每轮 GitHub 同步在近期采集之外，按持久化上界和游标、每批最多 50 条，对当前有效的已关联来源进行定点读取；游标随结果提交，租约恢复可继续推进。历史来源的定点结果不加入近期概览统计。

定点请求使用现有连接和平台读取适配，不需要 GitHub 写权限。开启连接定时周期后随周期刷新；未配置周期时不承诺自动刷新，由管理员通过既有同步入口触发。普通编辑成员建立关联不直接触发平台请求。已完成任务仍继续跟踪，解除关联后停止该关系的定点跟踪。

旧执行不能绕过连接版本与租约检查。结果提交还核对关联代次、仓库连接和项目绑定；解除后重新建立关系也不会接收旧关系的迟到结果。平台更新时间较旧时保留已有字段；相同时间内容矛盾时显示核实提示。来源更新和本地任务编辑分别写入，不相互覆盖。

无法读取、403、404、限流与凭证失效不作为删除证明。失败保留上次快照和成功时间，单独记录尝试时间和脱敏原因；部分来源失败显示部分成功，不宣称全部刷新完成。GitHub 转移或重定向不自动携带凭证跟随，也不自动跨仓库重绑。

### 解除、移动与升级

解除来源保留本地任务和最后快照；删除任务级联移除关系，不删除 GitHub Issue，以后可显式重新创建。有关联的任务要移动到其他项目，需先解除来源。仓库解绑、改绑其他项目、连接暂停、移除或失去管理权限后保留来源，但停止无效范围内的跟踪；恢复同仓库同项目的有效授权后可继续跟踪，已解除关系不自动恢复。来源记录首期不自动清理，需纳入备份与容量观察。

已有数据库应在维护窗口暂停写入和同步、完成备份后执行 `backend/src/main/resources/db/migrate-task-issues.sql`，再切换配套应用。迁移增加来源与关联表、快照的 Issue 编号及关闭原因、运行恢复游标；可重复执行，不自动转化已有 Issue 或任务。旧快照缺少编号时先由管理员重新同步，再创建或关联任务。全新安装的初始化顺序见 [部署流程](ci-cd.md)。

回退应用不自动删除新增结构。旧应用不知道关联约束和任务移动规则，不能直接恢复相关写入；应暂停写入与同步，选择配套版本或恢复经确认的备份。目标数据库迁移需单独安排，不能以容器重启代替。

## 来源变化待处理

近期开发记录、持久化来源和任务来源关联继续分工。IssueSource 保存最新成功读取的外部状态，任务关联保存上次确认基准；标题、打开或关闭状态、关闭原因存在差异时，任务显示“来源变化待处理”。链接、平台更新时间和同步健康信息不参与业务差异比较。待处理由差异推导，不另外维护开关；标题大小写变化也会识别。

任务看板卡片的“来源详情”展示基准到当前来源的字段差异，并支持“保留任务并确认”“完成任务并确认”和“重新开启并确认”。任务列表可筛选来源待处理，筛选沿用现有分页汇总后在已加载的任务上比较关联来源，不改变服务端任务查询语义。只读成员也可以查看详情和差异。

确认是 Workspace 内共享的任务处理决定，不是每个人独立的已读状态。拥有 TASK_WRITE 和 PROJECT_READ 权限的成员可确认，确认后记录主体 ID、时间并写入审计。保留操作只推进确认基准；完成操作要求当前来源已关闭且本地任务未完成；重新开启要求来源开放且本地任务已完成，目标状态为进行中。两个任务状态操作要求来源跟踪为 ACTIVE；跟踪失败、停止或等待时可查看旧数据并保留任务确认，但不能用不可用来源驱动快捷状态修改。

首次建立关系以当前持久化来源初始化基准，不提示初始差异，也不伪造用户确认人和时间。普通任务编辑、状态切换和同步不自动确认来源。重复读取相同业务内容不产生新变化；多个变化展示合并后的当前差异，若恢复到基准，待处理自动消失，不保留期间逐条事件。同步失败和停用不会清除基准或已有差异；界面继续显示错误及最近成功时间。

确认请求携带当前关联代次、来源业务版本、确认版本和用户所见任务版本。服务端在短事务中锁定并核对，连接、仓库与来源锁顺序与后台提交保持一致；任何版本不符返回 409 / TASK_ISSUE_CONFLICT，用户刷新后重新查看，不将迟到请求解释为确认新内容。基准推进与可选任务状态修改、审计同事务提交。任务普通更新、状态切换和依据笔记清除均递增版本；普通编辑、状态修改与删除也必须提交用户所见版本，详见 [任务编辑并发保护](task-concurrency.md)。

解除关联删除本次确认基准，任务和来源仍保留；重新关联产生新代次并以当前来源初始化，旧确认请求失效。来源刷新、Webhook 和整批同步不需要增加确认转发步骤，统一更新已有持久化来源即可。首期没有个人通知、自动修改任务、远端写回或完整变化历史。

已有环境需先完成前序迁移，在维护窗口暂停写入及同步并备份，执行 `backend/src/main/resources/db/migrate-source-confirmation.sql` 后部署配套应用。脚本增加任务与来源版本以及关联确认字段，以当前来源补齐已有关系基准，确认人和时间为空，不改变任务内容与状态。初始化标识保证重复迁移不会覆盖已确认基准或吞掉后续变化。全新安装由 Compose 在 Webhook 迁移后执行。回退前暂停确认和旧应用写入；旧版本不维护任务与来源版本，因此不得混合写入，回退期间的变化需要另行核实后再升级。

## GitHub Webhook 与指定来源刷新

Webhook 是来源变化的通知入口，不是第二套任务同步模型。事件只触发读取 GitHub 当前 Issue 状态，不直接套用事件正文；本地任务内容和状态仍由用户维护。只处理当前连接、当前仓库绑定及有效任务来源关系，未关联 Issue 不自动创建任务，PR 与 GitLab 不在此入口范围内。

### 配置与接收

Workspace 的 OWNER / ADMIN 在 GitHub 连接详情的“连接设置”中配置通知。首次填写 32 到 256 字符的随机 Secret，后续留空沿用，密钥以现有数据源加密密钥保护且不回显。页面提供接收地址，路由标识不承担认证职责。保存配置会递增版本并取消旧通知作业；轮换后同步更新 GitHub 的 Secret。

在 GitHub 仓库设置中手动添加 Webhook，使用页面对应的公开 HTTPS 地址，Content type 选择 application/json，仅订阅 Issues，并填写相同 Secret、保留 SSL 验证。本地回环地址不接受 GitHub 公网投递；系统不会自动安装平台 Webhook，也不需要扩大现有只读 Token 为远端写权限。

Gateway 为准确的回调路径提供独立 POST 路由，不加载浏览器 Session、不转发 Cookie 或 Authorization，Backend 独立对最多 1 MB 原始字节执行 HMAC-SHA256 验签。普通业务接口继续要求现有认证和权限。验签和持久化成功后返回 202，接收线程不请求 GitHub；数据库写入失败不能返回已接收。原始正文与 Secret 不进入投递记录，只保存摘要哈希、必要身份、动作和处理状态。签名约定见 [GitHub 官方文档](https://docs.github.com/en/webhooks/using-webhooks/validating-webhook-deliveries)。

### 去重、合并与恢复

同一端点的投递标识唯一，重复投递不会重复排队；同标识不同正文或事件类型返回冲突。ping、其他事件以及没有有效关联的 Issue 记录为忽略。接收时捕获关联代次，解除或重新建立关系后旧通知不适用于新关系。

后台每次最多领取 100 条到期通知，在现有连接队列空闲时生成 ISSUE_REFRESH 作业。同批同来源同代次合并为一个目标；运行中新收到的通知留待后续作业，避免吞掉处理期间的变化。指定刷新只查询该批目标，复用原 Tracker 的平台读取和提交校验，不遍历整条连接，也不推进批量游标。

来源结果、目标状态和运行进度同事务提交，崩溃后只读取尚未完成的目标。执行权依赖既有租约与连接配置版本，提交时还核对 Webhook 配置、关联代次、仓库连接和项目绑定。网络读取可在崩溃后重复，系统不宣称端到端严格只执行一次。

失败的投递最多自动处理三轮，各轮平台读取沿用现有有限重试；前两轮失败后分别等待约 60 秒和 120 秒，再次尝试。三轮耗尽后记录失败，管理员可从投递列表显式重试；重试仍校验当前配置和原关联代次，不能恢复失效关系。

定时整批校准补齐漏收通知和其他变化：到期校准优先于新通知作业，指定刷新不更新整批成功时间或推迟校准计划。未配置定时周期时仍需管理员手动同步，不承诺自动发现漏报。GitHub 侧接收失败可在平台投递记录中重投，系统内重试只覆盖已经成功持久化的投递。

### 可观察状态与停用

| 状态 | 含义 |
| --- | --- |
| RECEIVED | 已验签并持久化，等待合并排队 |
| QUEUED | 已关联到持久化刷新作业 |
| RETRY | 本轮失败，等待退避后的自动重试 |
| SUCCEEDED | 对应目标读取及提交已成功 |
| FAILED | 自动重试耗尽，可由管理员显式重试 |
| IGNORED | 不处理的事件、无有效来源或关联已变化 |
| CANCELLED | 连接权限或通知配置变化导致取消 |

投递列表展示动作、接收时间、尝试轮数、关联作业和脱敏原因；无效签名不进入已验签列表。配置已启用不代表一定可执行，连接、原主体权限和仓库绑定也必须有效。连接停用或删除、授权失效、通知配置停用及轮换均不能被旧执行绕过。

已有环境需在维护窗口备份、暂停写入与同步后执行 `backend/src/main/resources/db/migrate-github-webhooks.sql`，再部署配套版本；全新安装由 Compose 在任务来源迁移后执行。新增表保存通知配置、投递和指定目标，运行表增加通知配置引用；迁移不自动启用端点，不产生真实 Secret。已有数据卷不自动升级。回退前停用回调并暂停相关执行，不删除新增表，不用旧应用处理通知作业。

投递与指定目标暂无自动清理，应纳入备份与容量观察；删除连接后保留历史，当前管理入口随连接移除而不可用。用法还可参考 [GitHub Webhook 最佳实践](https://docs.github.com/en/webhooks/using-webhooks/best-practices-for-using-webhooks)。

## 故障恢复和断开连接

连接详情的“执行记录”页显示任务的等待、执行中、完成、部分成功、失败或取消状态，并保存脱敏原因。点击“查看明细”在抽屉中分页检查导入结果，重试本页失败项保留该项的原目标项目和项目状态；共享空间重试时需再次确认共享范围。重复请求使用幂等键与内容摘要校验；同一个键不能提交不同内容。

网络暂时失败与限流执行有限次数重试，耗尽后保留失败状态；权限或凭证失效不会导致工作台会话退出。部分能力失败时保留此前数据并明确提示列表可能是旧快照。后台执行崩溃后，租约过期可以重新领取；已经提交的导入成功项不会重复创建项目，已失败项由使用者主动重试。

404、403、凭证失效、枚举失败或范围变化都不作为删除证明。同步保留原项目、任务、笔记和源快照，并显示不可读取的原因。

解除仓库关联或删除项目后，自动导入不会把该仓库重新创建成项目；再次导入需要用户明确选择。项目删除继续执行现有任务保护规则。移除连接会停止执行、清除凭证并断开仓库，保留已导入的项目和快照；历史运行记录保留，但移除连接的管理入口不再可用。快照和历史运行记录当前没有自动清理任务。

## 契约与后续能力

API 位于 /api/workspaces/{workspaceId}，正式路径和字段以 [OpenAPI](../openapi/workstation.yaml) 为准。数据源接口从 4.0.0 引入，当前契约与全部 SDK 为 5.0.0，客户端需一起升级；不保留旧请求缺少新字段时的兼容更新行为。部署与发布仍沿用 [CI/CD 流程](ci-cd.md)。

当前连接使用 Token。OAuth、GitHub App、GitLab Issue 关联和远端写回属于后续能力，不能把现有同步开关视为这些功能已经实现。实际进度、验证结果、环境限制与待办事项统一见 [STATUS.md](STATUS.md)。
