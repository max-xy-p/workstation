# 工作空间邮箱邀请

共享空间的 Owner 和 Admin 可在空间设置中按邮箱邀请成员，无需对方提前登录过本系统。邀请角色为 Admin、Editor 或 Viewer，邀请不能授予 Owner；已有的按主体添加成员方式继续保留。

## 使用流程

管理员填写邮箱与角色后，Backend 在同一业务事务中保存邀请、专用邮件 Outbox 和审计事件，返回创建结果。此时对方还不是成员，也不代表邮件已送达。相同操作者、空间和请求标识只对应同一份邀请；参数发生变化时返回冲突。同一邮箱在一个空间内只能有一份未过期的待接受邀请，每个空间最多一百份待接受邀请。

后台将 Outbox 引用发布到 RabbitMQ，消费者调用独立邮件服务，再由邮件服务自己的 Outbox、MQ 和发送 Worker 调用 Resend。Backend 不持有 Resend 密钥，邮件服务不决定成员权限。列表中的“邮件服务已接收”只表示邮件服务完成持久化，不表示最终送达或用户已读。

被邀请人打开邮件链接，使用收到邀请的邮箱注册或登录，确认详情后明确点击接受。预览和接受都要求已认证的用户账号、匹配且已验证的邮箱；邮箱去除首尾空白后按不区分大小写处理，不合并 Gmail 点号或加号别名。机器账号不能接受邀请。预览不会消费邀请，也不会创建成员，避免邮箱扫描器访问链接就触发加入。

接受操作同步锁定空间，重新检查邀请状态、期限和邀请人的当前管理权限，在一个事务中建立成员关系、标记邀请已接受并记录审计。已经是成员时保留原有角色。重复接受只能由原接受者且仍为成员的账号进入，不会恢复后来被移除的成员关系，也不会覆盖后来变更的角色。并发接受、撤销和成员变更遵循相同的空间锁顺序。

## 有效期与撤销

邀请自创建起有效 23 小时。管理员可以撤销待接受邀请，已经发出的链接随即失效；撤销不能收回已经进入邮件服务的邮件。已接受邀请不能再撤销，应使用现有成员管理移除成员。邀请人失去成员管理权限后，其旧邀请不能继续用于加入。

首期没有独立的重新发送操作。需要再次邀请时，撤销旧邀请并创建新邀请；新请求生成新的链接及邮件请求标识。网络超时、MQ 重投和后台恢复属于原请求重试，沿用相同邮件标识，不会创建新的一批邮件。

## 可靠性与凭据

邀请链接使用随机 UUID 与独立签名密钥生成的 HMAC 凭据，业务库只保存摘要。链接凭据位于 URL 片段，浏览器读取后清除地址栏片段，登录过程中只在当前标签页的 Session Storage 暂存，登录回跳保存固定页面路径。后端通过请求体接收凭据，普通访问日志不应记录请求体；公开站点必须使用 HTTPS。

RabbitMQ 只传递 Outbox UUID，消息不包含邮箱或邀请链接。发布使用持久化消息、mandatory 路由检查和 Publisher Confirm。发布成功后仍保留未完成记录，一分钟后可补发，直到邮件服务接收或邀请终止；发布领取使用短租约与条件更新，旧发布者不能覆盖消费者完成的状态。

消费者不在网络调用期间占用数据库事务。邮件服务使用稳定的邀请 ID 作为 requestKey，相同内容重试返回原邮件任务；如果服务已经保存邮件但响应丢失，后续仍提交完全相同的请求。数据库失败或网络故障通过 MQ 的十秒延迟队列恢复，邀请过期后停止处理。该链路为至少一次处理加幂等保护，不承诺跨服务的严格恰好一次。

邀请邮箱、历史及投递元数据属于敏感业务数据，应限制数据库访问并纳入备份。首期不自动清理邀请历史，列表只展示最近一百条；邮件正文清理沿用邮件服务策略。

## 启用、升级与回退

邀请默认关闭。启用前备份业务库，在维护窗口执行 [邀请迁移](../backend/src/main/resources/db/migrate-workspace-invitations.sql)，部署配套 Backend、Frontend，启用 RabbitMQ 监听，并核对 Keycloak 访问令牌包含 email 与 email_verified 声明。迁移可重复执行；已有数据卷不会因重启自动升级。全新 Compose 环境自动在基础表之后执行此脚本。

配置 INVITATIONS_ENABLED、独立随机生成的 32 字节 Base64 INVITATIONS_SIGNING_KEY，以及正确的 WORKSTATION_PUBLIC_URL。Backend 使用 MAIL_SERVICE_URL 与 MAIL_BACKEND_TOKEN 调用邮件服务；Compose 已配置内部地址并复用 Backend 专用凭据，不使用 Keycloak 的调用凭据。完整配置以示例文件为准。

各 Backend 实例必须保持签名密钥、公开入口和应用时区一致。签名密钥、入口或时区变更前先处理待发及待接受邀请，避免稳定邮件请求的内容发生变化或旧邀请无法投递；密钥应单独备份。邮件服务自身的密钥、发件域名和 Resend 配置见 [邮件服务](mail.md)。

本次公共契约与全部 SDK 为 5.1.0，兼容新增接口，原成员接口保持不变。回退前关闭邀请入口和投递，处理尚未完成邀请；回退镜像不会撤销已经建立的成员关系。当前验证结果和部署待办统一见 [项目状态](STATUS.md)。
