# 邮箱验证与事务邮件

Workstation 使用账号密码登录。注册邮箱通过邮件中的六位验证码验证；之后日常登录无需再次收取邮箱验证码。忘记密码也使用邮箱验证码，在原认证页面验证通过后才能设置新密码，设置完成后必须重新登录。Keycloak 负责账号、验证码、有效期和验证结果，邮件服务只负责投递。验证成功不授予其他 Workspace 的访问权限。

## 发送边界

同仓库的 Mail Service 独立构建和部署，使用独立 MySQL 数据库与账号。Keycloak 验证码步骤生成中文验证码正文，并通过邮件发送扩展交给内部接口，Mail Service 加密保存任务后返回接收结果，随后调用 Resend HTTP API。Keycloak 不持有 Resend 密钥，不直接连接 Resend SMTP。

内部接口同时为后续业务事务邮件保留独立的 Backend 调用身份。浏览器没有发信权限，Nginx 不公开内部发信接口。内部 HTTP 仅用于同一受控容器网络；跨主机调用应使用 HTTPS 和网络访问限制。内部邮件契约见 [`../openapi/mail-service.yaml`](../openapi/mail-service.yaml)，不改变公共 Workstation API 或已发布 SDK。

验证码页面沿用 Keycloak 原生主题布局，邮件正文只有验证码和使用说明，不包含邮箱验证或密码重置链接。本轮覆盖注册及未验证邮箱的 VERIFY_EMAIL 动作与找回密码的邮件步骤；修改邮箱 UPDATE_EMAIL、身份提供商关联及管理员操作邮件不在替换范围内。其余原生邮件仍复用邮件发送扩展。业务邮件的触发条件、收件人授权和内容由业务调用方维护。未来业务通知若需要与业务提交一致，应在 Backend 的业务事务中写入专用 Outbox，提交成功后再转交邮件服务。当前没有新增邀请、任务提醒等业务触发器，也没有复用审计事件充当邮件任务。

## Resend 与 Cloudflare 配置

在 Resend 添加并验证自己控制的 `12718080.xyz`，将 Resend 提供的 DNS 记录按其要求添加到 Cloudflare，保留现有站点及收信记录。不要为同一 DNS 名称叠加多个 SPF 记录，应按服务商要求合并。完成 DKIM、SPF 及适当的 DMARC 配置后，使用域名范围的发送密钥。

默认发件人为 `Workstation <noreply@12718080.xyz>`，可以通过环境配置更改。仅发信不要求给这个地址购买收件箱；如需回复，配置一个实际可收信的回复地址。完整运行参数以根目录 `.env.docker.example` 为准，Resend 密钥不进入源码、镜像构建参数或浏览器。

邮件服务还需要独立数据库密码、Keycloak 与 Backend 各自不同的随机调用凭据，以及一个 Base64 编码的 32 字节随机加密密钥。生成方式见根 README。加密密钥须备份；更换前先排空待发任务，否则旧任务无法解密。服务不提供不安全的默认密钥或静默 SMTP 回退。

## 新安装与已有部署

全新 MySQL 数据卷由邮件初始化脚本创建独立数据库与账号，邮件服务启动时建立自己的任务表。配套 Keycloak 镜像包含与其版本匹配的邮件发送扩展，首次导入 Realm 模板即启用邮箱验证及 `workstation.email-code.enabled` Realm 属性。扩展沿用 `VERIFY_EMAIL` 与 `reset-credential-email` 原生标识，通过优先级替换实现；仅属性为 true 的 Realm 使用验证码，其余 Realm 保留原生链接流程。扩展固定匹配 Keycloak 26.7.3，升级身份中心版本前必须重新验证 SPI 兼容性。

已有部署升级前，先备份业务库、Keycloak 库和配置，准备新环境变量及配套五个镜像。在已有 MySQL 容器内通过环境变量提供邮件数据库账号和密码，并执行 [`../mail-service/init-database.sh`](../mail-service/init-database.sh) 创建独立邮件库及授权；该脚本不会清空数据，可重复执行。不要依赖重新挂载初始化脚本或重启 MySQL 为已有数据卷完成升级。

先启动邮件服务与配套 Keycloak，确认邮件服务可接收任务，并通过身份中心的测试邮件确认实际收到邮件。随后从仓库根目录运行邮件升级工具进行只读预览，确认后使用其 `--apply` 选项启用既有 Realm 的邮箱验证。工具不重导 Realm、不修改用户、角色、客户端或已有邮箱验证标记；更改现有策略前须确认未验证用户仍能访问自己的邮箱。既有已验证用户无需重复验证，未验证用户在后续登录时按 Keycloak 流程验证。

已有邮件部署切换验证码时，先备份身份数据库并部署新的 Keycloak 镜像。使用 [验证码升级工具](../scripts/configure_email_codes.py)，从根目录以 `python -m scripts.configure_email_codes --base-url <身份中心地址>` 预览，确认后加 `--apply`。管理员凭据从 KEYCLOAK_ADMIN_USERNAME / PASSWORD 环境变量或交互输入提供，不自动读取 .env.docker。工具核验两种扩展的版本标记、原生找回密码的选择用户、验证邮箱及更新密码必需步骤，再启用 Realm 属性并将用户操作流程有效期限制到最多 300 秒，保留已有更短期限和其他属性。缺少扩展或流程被定制时拒绝写入；不覆盖用户、凭据、角色、客户端或认证流程，重复应用幂等。已有链接不会变成验证码，切换后应从登录页重新开始注册验证或密码重置。

工具保留已有 SMTP 配置中的其他字段，但配套扩展实际使用的是 Mail Service。公开注册配置工具同样保留现有邮箱验证策略，避免再次运行后关闭验证。完整注册及个人 Workspace 边界见 [`registration.md`](registration.md)。

回滚前排空或暂停邮件任务，确认旧 Keycloak 的发送渠道和邮箱验证策略；仅回滚镜像不会撤销 Realm 变更。不要删除身份库或邮件库来回滚。

## 验证码与身份边界

验证码使用安全随机数生成，五分钟有效。Keycloak 的共享一次性对象存储保存带随机盐的 HMAC-SHA256 摘要；密钥来自 Realm 自身，原始验证码只在邮件提交期间存在。缓存键与内容绑定 Realm、用户、当前邮箱、认证会话及标签页、客户端和验证用途，注册码不能用于重置密码，修改邮箱或切换认证会话后需重新获取。Realm HMAC 密钥轮换或验证码缓存丢失时，未完成的验证码流程应重新获取，不降低验证要求。

单个验证码最多尝试五次，计数与成功消费使用存储的原子操作；并发正确提交只有一个成功者。重发前使旧对象失效，页面刷新不发信；按用户及用途共享六十秒冷却和每个自然小时五次额度，同一来源 IP 在十分钟时间窗口内最多申请二十次，跨账号、用途共享。邮件服务未接收时当前验证码失效，不能因为发送接口异常继续通过。服务接收成功仍不等于供应商实际送达。

找回密码对不存在、禁用或没有邮箱的账号显示相同验证码页面和说明，不发信且不能通过校验；重置入口不通过发送失败或账号限流提示暴露账号是否存在。验证码成功只推进原生密码更新动作，不直接签发登录凭据；保留密码策略及认证流程的有效期和会话校验，更新成功后结束重置流程，用户需重新登录。浏览器和 Backend 没有新增匿名验证码接口、账号状态或密码存储。

验证码消除了邮件链接的本地地址与邮箱安全中转兼容问题，不解决邮件过滤、延迟或退信；公开部署仍需真实 HTTPS 入口，SMTP/API 凭据和验证码不得进入浏览器地址栏、日志或仓库。

## 投递与故障处理

内部接口返回接收成功仅表示任务已经持久化。任务使用调用方和请求标识去重；相同标识只能对应完全相同的正文与到期时间。调用方遇到超时应使用同一个请求重试，不能生成新的标识。Keycloak 适配器在单次发送调用的网络重试中保留相同请求。

投递任务使用短租约领取，进程退出后可恢复。整个邮件库共用每秒一次的发送时钟，供应商限流会触发共享冷却。临时网络错误、限流和部分供应商故障有限重试，永久拒绝停止重试。发送任务最长保留 23 小时的有效窗口，最多尝试八次；普通 Keycloak 邮件投递期限不超过十五分钟及 Realm 用户操作链接期限；验证码邮件额外限制到该验证码的剩余五分钟，过期验证码不再排队投递。重试采用稳定的 Resend 幂等键，不跨越其 24 小时幂等窗口。

Resend 接收后状态为 `SUBMITTED`，服务清除正文。如果需要投递状态，在 Resend 为站点的 `/mail/hooks/resend` 配置回调，并将对应签名密钥放入运行环境。关注送达、延迟、退信、投诉和失败事件；未配置密钥时回调关闭，状态停留在供应商已接收，不伪称已送达。回调校验原始请求签名及五分钟时间窗，支持重复、乱序以及先于发送响应到达的事件。`DELIVERED` 仅表示收件服务器已接收，不保证进入收件箱或已读。

待发正文及收件地址以 AES-GCM 加密保存，到期或终止时清除；投递和回调元数据保留三十天后清理。数据库备份仍应作为敏感数据保护，历史备份不会随在线清理自动删除。Resend 可能按其自身策略保留邮件内容，应另行核对供应商的数据保留设置。

邮件服务故障时，账号密码校验和已有会话仍由原认证链路管理；需要验证邮箱、重置密码的用户可能暂时无法完成对应操作，应检查任务状态和发送渠道，不能通过批量标记邮箱已验证绕过故障。
