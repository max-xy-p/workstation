# 笔记实时编辑状态

打开已有笔记后，编辑区工具栏下显示其他在线成员正在查看或编辑。一个用户的多个页面合并为一条，任一页面近期编辑时显示正在编辑；自己的页面不计入其他成员。只读成员可以查看和报告查看状态，不能报告编辑状态。

这是协作提示，不提供排他锁、光标共享或正文实时合并。保存、自动保存、历史恢复和 IndexedDB 草稿仍遵循既有版本条件更新；其他成员也在编辑时会显示保存冲突提醒，不能据此跳过版本校验。

## 状态与通信

浏览器通过带 Cookie 和 CSRF 的 HTTP 请求报告页面状态。进入时报告查看，标题、正文或属性出现用户输入后报告编辑；约十五至二十秒没有输入、窗口失焦或失去编辑权限后恢复查看。每十秒续租，隐藏标签页、离开笔记或退出页面时尝试报告离开。恢复可见后使用新的页面标识，避免旧请求影响新租约。

Backend 每次操作都验证用户身份、当前 Workspace 权限和笔记存在性，用户资料从当前成员记录读取。页面标识只标识该用户的一次页面生命周期，不是凭据；同一页面请求使用递增序号，旧序号不能覆盖新状态，已离开的页面不会被迟到续租重新激活。离开标记保留两分钟，之后清理；异常延迟超过保留期的请求仍依靠短租约收敛，不提供永久事件去重。

Redis 使用 Lua 原子维护每页四十五秒租约与状态，采用 Redis 时间，并在同一笔记的 Hash Tag 内操作。租约超时后查询会移除旧状态；没有访问的 Key 最多一百五十秒自动过期。不扫描全部 Redis Key，不使用 Redis Pub/Sub。每篇笔记最多保留二百五十六条页面记录（包括短期离开标记），单用户每篇笔记最多十个活跃页面。

状态更新后，RabbitMQ 将不含用户资料与正文的笔记主题广播给各 Backend。每个实例使用独立的临时独占队列，断线后自动删除，无需配置实例标识；旧提醒最多保留十秒，队列最多一千零二十四条。它只提醒重新查询当前状态，不用于保存通知或记录编辑历史，因此不复用通知的持久化队列、Outbox 或事件去重表。

Backend 通过 SSE 发送无业务内容的 refresh 事件，浏览器随后请求在线状态快照。传输复用通知的有界 SSE 实现，主题和容量分别隔离；每节点最多五百条在线状态连接、每用户最多五条，十五秒心跳，连接最多五十五秒且不能超过访问令牌有效期。新连接立即提醒查询，浏览器还每五秒补查，覆盖提醒丢失、消息乱序、租约自然过期与重连窗口。

## 故障和权限变化

MQ 不可用时，Redis 中已经完成的续租继续有效，HTTP 补查仍能更新提示。Redis 不可用时，快照明确返回不可用并清除旧显示，续租返回独立错误；界面显示在线状态暂不可用，不显示无人在线，也不阻止正文保存。新打开的页面和断线恢复始终读取当前状态，不回放过去的编辑提醒。

每次快照批量检查当前成员资格，移出空间的成员不会继续显示；编辑者降为只读后，即使旧租约尚未过期也只显示查看。读取者被移出空间、笔记删除或会话失效后，后续请求会被拒绝，浏览器关闭状态连接并清空资料。已打开的 SSE 只含刷新信号，不能直接读取成员资料或正文。

该状态不写入 MySQL，也不写入浏览器 IndexedDB。MySQL 仍是笔记正文、版本、成员关系与持久通知的真源；在线租约丢失后由活跃页面重新建立。

## 启用与升级

默认关闭。配置 NOTE_PRESENCE_ENABLED 为 true，使用已有 Backend Redis 和 RabbitMQ 连接，并启用 RABBITMQ_LISTENER_AUTO_STARTUP。所有 Backend 实例应使用相同的 Redis 与 Broker，连接参数和权限沿用现有示例；无需新 Secret 或数据库迁移。

需要配套部署 Backend、Gateway、Frontend 及 Nginx。代理必须包含笔记在线状态流的专用路径，关闭缓存、缓冲和压缩，并允许长响应；仅更换前端无法提供跨实例更新。关闭功能后不再创建连接或续租，旧租约会自行过期。

公共契约与全部 SDK 为 5.3.0，新增查询快照、更新页面状态和 SSE 接口，已有笔记写接口不变。浏览器使用 EventSource，生成的 Python SSE 方法仍是完整文本响应，不是增量订阅工具；机器主体不能访问个人在线状态。验证结果和目标环境待办见 [项目状态](STATUS.md)。
