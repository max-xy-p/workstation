# 任务编辑并发保护

任务的标题、描述、所属项目、状态、优先级、截止日期和依据笔记共同使用 tasks.version。编辑、状态修改及删除必须提交用户读取时的 expectedVersion，服务端按 Workspace、任务 ID 和版本执行原子条件写入。完整更新和状态修改成功后版本加一；删除成功移除任务及来源关系。创建不要求版本。

版本不匹配返回 409 / TASK_VERSION_CONFLICT；任务不存在或已删除返回 404；未提供版本、负数或非法参数返回 400。失败不记录成功审计，不提交来源等附带修改。来源“完成并确认”“重新开启并确认”复用任务状态的条件更新，与确认基准、审计同事务；依据笔记清除继续递增任务版本，使旧编辑会话失效。

## 冲突后的操作

完整编辑冲突后保留当前表单，读取并展示最新任务与当前输入的全部可编辑字段。用户可以保留输入并显式采用刚查看的版本继续编辑，再次点击保存；也可以明确选择用最新任务内容替换当前输入。系统不自动获取新版本后覆盖保存。读取失败可重试读取，尚未核对时禁用保存；任务删除或不可访问时继续保留可复制的输入，不自动重建任务。

状态修改冲突后，卡片恢复到原来展示的状态，并打开对照面板。删除冲突也先展示最新任务。用户可以取消操作，或按已查看的版本明确重试；再次发生竞争仍返回冲突并重新要求核对。处理期间防止重复操作与关闭面板，查看权限不授予写入能力。

该机制是整个任务的乐观锁，不自动合并不同字段。服务端为项目、笔记和来源关系约束保留必要的短事务锁；不在用户编辑期间持有数据库锁。页面刷新或关闭仍可能丢失未保存表单，当前没有新增任务草稿持久化。

## 升级边界

契约和全部 SDK 为 5.0.0。完整更新使用由 TaskRequest 派生的 TaskUpdateRequest 强制 expectedVersion；Backend 复用同一个任务请求模型，不建立另一套字段。状态请求必须带版本，删除通过查询参数携带版本；TaskResponse.version 为必填。旧客户端未提交版本的写操作会失败，应用、Frontend 与 SDK 应配套升级，禁止用默认版本或自动重试兼容旧客户端。

复用此前 migrate-source-confirmation.sql 增加的版本字段，本轮没有新增数据库结构。未执行前序迁移的环境应先按已有部署顺序备份升级；本轮不自动执行目标环境迁移。更多进度与真实环境验收事项见 [STATUS.md](STATUS.md)。
